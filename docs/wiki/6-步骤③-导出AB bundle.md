# 6. 步骤③：骨骼映射与导出 AB bundle

最后一步：核对骨名映射，把作者模型 + 贴图打成一个 **AssetBundle**，放进游戏测试。

> 这一步在 0.9.0 变化最大。旧版这里叫「校验与导出模组」，导出的是 3DMigoto 包；现在导出的是真正的 Unity AssetBundle，由游戏引擎原生蒙皮。

## 6.1 骨骼映射表

导出前先把**你的骨名**对到**游戏骨名**。表格在本步骤面板的「骨骼映射表（源骨 → 游戏骨）」
折叠区里，先点 **`扫描源骨骼`** 才会列出来（`列出全部` 连没权重的也列，`✕` 清空）。

**一行 = 一根带权重的源骨**，从左到右五格：

| 格子 | 是什么 |
|---|---|
| 源骨名 + 图标 | 只读。✓=已指定游戏骨，·=用了物理策略，⚠=两样都没有 |
| 百分比 | 这根骨占总权重多少，用来判断值不值得管 |
| 🖌 | 点开看这根骨具体刷在哪些顶点上 |
| **目标游戏骨** | 下拉，可打字搜索。**身体骨填这个** |
| **装饰物理策略** | 下拉。**飘带 / 花边这类填这个** |

> **两个下拉是互斥的**：一旦选了目标游戏骨，同一行的物理策略就自动变灰——已经确定映射到
> 哪根游戏骨了，装饰物理对它没意义。所以每行**二选一**，不是两列都要填。

- MMD / Mixamo / Rigify / SCSP / VRM(VRoid) / 3ds Max Biped / Auto-Rig Pro / 英文 Humanoid
  **八家预设自动预填**，命中的话身体骨一行都不用碰；
- 预设认不出来的（自定义骨名、`bone_<hash>`）逐行点选即可，实测约 21 行能覆盖全身；
- SCSP 源导出的骨名常带 `_1` 后缀（`LeftElbow_1`、`LeftArm1_rot_1`）。**0.9.3 起查预设会自动
  剥掉这个后缀**，脚趾也补进了预设表——此前这类源会有一批带权重的身体骨不预填，脚趾还会
  撞承重关节闸门。实测 dress-2219 不填任何手写表就自动映射 146 条、承重关节 21/21 全覆盖；
- 表可以 `存为 JSON` / `从 JSON 读入`，同一套骨架的第二个 mod 直接复用。

> 折叠区底部还有 **`装饰物理覆盖`** 和骨映射 JSON 两个文件路径栏——它们和上面这张表等价，**表里填过的优先**。表能满足就不用碰这两栏。

**装饰物理策略**替代了旧版手写的 `physics-override.json`：

| 策略 | 用在哪 |
|---|---|
| 自动 | 默认，按源父骨和语义猜 |
| 刚性跟父骨 | 硬质配件（扣子、徽章），不会炸的保底 |
| 自建摇物链 | 飘带、蝴蝶结这类要自己摆动的（⚠ 见下） |
| 跟裙摆 | 裙边花边，蹭最近的裙摆骨 |
| 跟指定骨 | 上面都不合适时手动指定 |

> ⚠️ **「自建摇物链」尚无稳定的画面级成功案例，是下一个开发重点。**最近一次实测：链建好了、日志全绿，
> 装饰件在游戏里仍然维持静止姿态。正在查，暂时的推荐做法是——
> **裙子和裙边花边用「跟裙摆」**（蹭游戏自带的裙摆骨，连摆动带碰撞体一起继承，确定有效），
> **蝴蝶结、缎带、硬配件用「刚性跟父骨」**（形状正确、不飘不抽）。

> 装饰骨的物理归属**名字和位置都决定不了** —— 源作者常把腰饰绑在胸骨、把裙边花边绑在大腿上。插件的目标不是猜准，而是默认给一个不会炸的，再由你一句话覆盖。

> 📷 **待截图**：`images/step3-bonemap.png` —— 骨骼映射表，含预填行与手动点选行。

## 6.2 承重关节闸门（会拦住你的那个东西）

导出前插件会检查 **21 个承重关节**有没有拿到权重：

```text
Hips / Spine / Spine1 / Neck / Head
Left|Right Shoulder / Arm / ForeArm / Hand
Left|Right UpLeg / Leg / Foot / ToeBase
```

`Spine2` 故意不在闸门里：游戏有三节脊椎，Auto-Rig Pro 等源只有两节，拦它等于误伤所有两节脊椎的源。

**缺任一根直接拒绝导出，并点名是哪根。**这条闸门存在的原因是实战教训：源骨名认不出来时，旧版是**导出成功、进游戏才发现废了**——整只手被钉在 `Spine1`、上臂挂在袖子的摇物骨上，全程零警告。

判据只看游戏侧，与你的源命名无关；与目标骨架取交集，所以**发型 / 发饰导出永远不会触发**（交集为 0）。

被拦住时：回映射表，把被点名的关节对应的源骨指对。若你的模型那块本来就没刷权重，那得回建模软件补。

## 6.3 面板上那两个空要填什么

导出区有两栏是空的，第一次用必须填，填完 Blender 会记住：

### `R32 模板 bundle`

目标 body / hair 的 **R32 模板 `.bundle`** 文件。模板是工具作者一次性批量产的（530 个 body +
378 个 hair），按目标资源名取对应的那个，例如换 `mdl_chr_atbm-cstm-0140_body` 就选同名模板。

模板整包**在百度网盘提供**（`libraries\templates\`），不在 GitHub 仓库里，见 [[1-环境准备与安装]] 1.1「网盘素材包」。

**留空也能导出**，只是只出 `bundle-src\`（中间产物），不会打成成品 `.bundle`。

### `外部 Python`

打包这一步不开 Unity，而是用 UnityPy 把你的数据灌进模板。这需要一个**你自己装的 Python**——
**不能是 Blender 自带的那个**，它没有 UnityPy。

| 要求 | 说明 |
|---|---|
| 版本 | **3.10 或更高**，推荐 3.11 / 3.12。下限由 Pillow 决定，不是插件的限制 |
| 依赖 | `pip install UnityPy Pillow` |

这一栏填什么：

- **默认值 `python`** —— Python 装好且在 PATH 上就不用改，直接能用；
- **填绝对路径** —— 不在 PATH、装了多个版本、或者用虚拟环境时。Windows 上典型长这样：

  ```text
  C:\Program Files\Python\Python312\python.exe
  ```

不知道自己的在哪，命令行跑：

```powershell
python -c "import sys;print(sys.executable)"
```

把打印出来的路径原样粘进去即可。

> ⚠ 两个坑：
> - **别填 Blender 目录里的 python.exe**（`...\Blender 4.2\4.2\python\bin\python.exe`），
>   插件本体就跑在它上面，但它没有也不该装 UnityPy；
> - Windows 上 `C:\Users\<你>\AppData\Local\Microsoft\WindowsApps\python.exe` 可能是
>   应用商店的**占位程序**，点了只会弹商店。装了真 Python 却报找不到模块时，先确认命中的不是它。

## 6.4 导出

- 填模组信息：`模组标识`（文件名与目录名，用它区分 mod）、`模组名称`、`作者`；
- **描边设置**：body 填 **`描边颜色`**（游戏描边读顶点 COLOR，新网格必须由插件写入），
  发型填 **`发型描边色档`**；两者都有 **`描边宽度`**（见 [[7-发型与发饰]]）；
- 点 **`导出并打包 bundle（一键，需外部 Python）`**。

> **按钮是灰的？**面板有两道前置闸门，没满足就点不动：
>
> | 灰掉的按钮 | 面板提示 | 怎么解 |
> |---|---|---|
> | `导出 bundle 源` | 「bundle 源需要作者模型顶点组权重」 | 激活的网格没有任何顶点组。插件不刷权重，回建模软件绑好再来 |
> | `导出并打包 bundle（一键…）` | 「一键打包需先选 R32 模板 bundle」 | 上面那栏 `R32 模板 bundle` 还空着，见 6.3 |
>
> 只要 `bundle 源` 那个是亮的，就算不填模板也能导出中间产物。

产物：

```text
<输出目录>\<模组标识>\
  <模组标识>.bundle     成品 AssetBundle
  mod.json              运行时读的清单
  bundle-src\           中间产物，排错时看
```

## 6.5 发型 + 发饰：合并成一个包

发型和发饰是同一件头饰的**两个 renderer**（`Geo_Hair` + `Geo_HairProp`），必须进同一个包。
导出方式是固定的：

1. **激活「发型」作者网格**（不是发饰）；
2. 在导出框的 **「发饰对象」** 里选上发饰网格；
3. 点导出，插件把两个 renderer 打进一个包。

- **不做发饰**：「发饰对象」留空即可，导出只替换 `Geo_Hair` 并保留原配套发饰。面板会提示
  “只换发型，发饰保持原版”。多套发型共用同一基础网格时，步骤①匹配配置档那一步会用同帧
  `Geo_HairProp` 的顶点数选中正确的目标资源；
- **激活发饰去导出会直接报错**。只带 `Geo_HairProp` 一条规则的包实测装上去的效果是：发饰换了，
  **发型退回原版**——因为包里没有 `Geo_Hair` 规则，运行时不会碰它。日志里的特征是
  `pairs=1`（正确的合并包是 `pairs=2`）。

导出的 `mod.json` 里应该看到两条 renderer 规则，副 renderer 自带 `source` 和 `skeleton`：

```json
"renderers": [
  { "rendererId": "hair",     "targetRenderer": "Geo_Hair",     "modRenderer": "Geo_Hair" },
  { "rendererId": "hairprop", "targetRenderer": "Geo_HairProp", "modRenderer": "Geo_HairProp",
    "source":   "mdl_chr_<资源名>_hair__Geo_HairProp",
    "skeleton": "Assets/Mods/<模组标识>/mdl_chr_<资源名>_hair__Geo_HairProp_bones.json.txt" }
]
```

详见 [[7-发型与发饰]]。

## 6.5.1 材质槽会被归并到目标段数

作者网格常带多个材质槽（发型模型的 `m_FrontHair` / `m_BackHair` / `m_InBack`，身体的多件衣料），
而游戏目标只有固定段数：发型和发饰各 **1 段**，身体是 **1 段（bdy）、2 段（bdy + bdyco）或
少数 3 段**（`cstm-0119` 全系列等 18 套，多出来的是腰环、胸前小件这类零碎）。
导出时插件会把作者材质槽归并到目标段数——**前提是这些槽共用同一套贴图**（同一张 atlas）。

没归并成功时的表现是模板补丁报
`submesh count changed: template=1 input=3`。身体上若把标了「原生 co」的槽导到只有 1 段的目标，
会得到明确报错，改回「不透明」或换含 bdyco 的目标服装。

> **目标有 3 段不代表你要准备 3 套贴图。**贴图只按你真正用到的段出，你没用到的段保留原版
> 材质（它在你的模型里是 0 面片，看不见）。所以做一件普通不透明衣服，即使目标是 3 段，
> 也只填「基础色 t0 / 混合遮罩 t1 / 暗面材质 t4」这一套就够，co 那三栏留空。

## 6.6 安装到游戏

把整个 `<模组标识>\` 目录放进：

```text
<游戏目录>\gakumas-mod\mods\
```

进游戏 → 主页菜单 → **Mod 管理** → 在「服装 / 发型」分页里打开开关。开关会同时改**当前会话**和下次启动的配置。

> 用 chinosk6 的 `gkms-localify-dmm` 加载则是它自己的 `<游戏目录>\gakumas-local\local-files\mods\`，
> 没有游戏内管理页。两个目录互不读取，别放错。

> 同一件服装 / 同一个发型**只允许一个 mod 开启**。已有 mod 开着时新的会被拒绝并显示占用者。

## 6.7 导出报错怎么办

| 报错 / 现象 | 原因 | 处理 |
|---|---|---|
| 承重关节缺权重被拒 | 源骨没映射，或模型该处无权重 | 回 6.1 映射表 / 回建模软件补权重 |
| 提示配置档没有透明部件 | 材质槽选了「原生 co」但这套服装本身没有透明件 | 改回「不透明」或换含透明件的抓帧重新生成配置档，见 [[8-透明材质（原生co）]] |
| `材质槽 N 缺少 t0 基础色贴图` | 有材质槽标了「原生 co」，但 **co 那三栏的 t0 是空的**（co 的 t0 不会回退借用 body 的） | 补上 co 自己的 t0；这件衣服其实不需要透明件的话，把该槽的 `渲染材质` 改回「不透明」。**插件 0.9.3 之前**还有一种情况：目标服装有 3 段时，即使你一个 co 槽都没标也会报这句——升级到 1.0.0 即可 |
| 提示找不到 Python 可执行文件 | 「外部 Python」填的名字不在 PATH | 填绝对路径，见 6.3 |
| 打包脚本报 `No module named UnityPy` / `PIL` | 外部 Python 没装依赖 | `<你的python.exe> -m pip install UnityPy Pillow` |
| pip 装 Pillow 时报版本不兼容 | 外部 Python 低于 3.10 | 换 3.11 / 3.12，见 6.3 |
| 进游戏没描边 / 颜色错乱 | 顶点 COLOR / 贴图问题 | 见 [[9-常见问题与排错]] |
| 进游戏模型错位 | 作者模型没对齐参考身体 | 见 [[4-步骤①-准备配置档]] |

排查时保留 `bundle-src\` 和 runtime 的 `gakumas-mod\mod-plugin.log`，日志会写明命中了哪个 renderer、替换了几个目标。
