## 0. 动手前必查清单

按顺序检查,任何一项不过都别往下走:

1. **左右镜像判定(最容易翻车,必须最先确认)**
   - 插件的坐标约定是 **「Blender 所见 = 游戏画面的镜像」**。判据:游戏参考骨架
     `Geo_Body_Armature` 的 `Right*` 骨骼位于 Blender 场景 **+X** 侧(角色面朝 -Y 时,
     +X 是角色的**左**手边)→ 参考体在 Blender 里是镜像显示的。
   - mmd_tools 导入的 PMX 手性是"正"的(贴图文字可读)→ **必须先对模型整体做 X 镜像**,
     否则印花、手表等不对称元素进游戏后左右颠倒、文字反写。
   - 快速自检:模型有文字印花时,**Blender 里反写 = 游戏里正确**。
   - 镜像内容:网格 x 取反 + 全部 shape key 同步 + 翻转面朝向(flip normals)+
     自定义拆分法线镜像((poly,vert) 键重建)+ 骨骼 head/tail.x 取反、roll 取反。
     脚本:`mirror_only.py`(独立执行)或 `rebuild_all.py` step0(全流程内)。
   - 镜像两次 = 还原,进游戏发现方向反了再跑一次即可回退。
2. **姿势参考以指定文件为准**:必须用含 **T-pose 游戏骨架 + GMI 权重参考体**的 blend。
   别信任意 blend 里的骨架姿势——踩过"参考骨架实际是 37° A-pose 摆拍状态"的坑。
3. **网格必须挂着指向模型骨架的 Armature 修改器**。修改器一丢,缩放/烘焙会被静默跳过
   (脚本报成功、文件没变化)。规范:脚本开头断言修改器存在;烘焙前做网格级断言(见 §2)。
3b. **绑定完整性基线** ⭐v3:坏绑定静止完全看不出、会一路混到游戏里才炸,且导出侧无法补救(见 §2 v3
   教训),所以必须在 prep 阶段自己盯。**唯一实测可靠的方式是「同模型前后对比」,不要用绝对阈值**:
   - 动手前量一次基线,prep 每步之后复量同一组数,**只允许变小或不变**。dress_2219 实测:手指
     「骨到其主导顶点质心距离」16.0mm(prep 前)→ **50.5mm**(prep 后);全身该比值 p95 1.18 → 2.16。
   - ⚠**别把「距离 ÷ 骨长 > 1.0」当绝对判据**——已实测证伪:健康且实机能跑的模型里这很常见
     (madoka max 2.74、miku max 4.66/35 根超标),因为 `*_rot`/`*_H` 捻骨与辅助骨骨长极短却天生
     驱动远处几何。同理「主导骨是否为最近骨」也不可用(SCSP `_1` 双链同位置互相竞争排名,
     实测坏绑定 top1=43% 反而高于健康的 31%)。
   - 功能性判据见 §2 步骤 6 ①(姿势模拟),那个能跨模型用。
4. **材质精简 / 删头** ⭐v2:游戏保留原头,删掉脸/发/头部件。复杂 MMD 光按材质删不够——
   发饰(花/夹/丝带)常挂在 Up_Flower 等**身体材质**上浮空在脖子上方,且和身体件无干净 z 分界。
   正解=双判据:「材质∈HEAD_MATERIALS」**或**「顶点权重主要(>0.5)在 `頭` 骨及其后代」的面都删,
   再 delete_loose(chisaki `02_prep_body.py` step2)。帽子/发带归 HEAD_MATERIALS(用户确认脖子以下)。
5. 记录源模型原始状态(领口顶 z、手尖 |x|、材质/UV),供最终复验对比。
5b. **体型基线按露肤度定**(圆香泳装 v6→v8 实战教训,动手前必须先定):
   - **露肤少的服装(裙子/裤子/长袖)**: 可完全保留 mod 源模型体型,只做关节对齐——
     肉量分布差异被衣服盖住,看不出来。
   - **露肤度极高的服装(泳装/浴装)**: 必须把皮肤区变形到**目标角色原生体型**
     (胸/腰/肚脐位置、脖长、腋下全暴露,关节对齐管不到关节之间的肉,观众基线是
     目标角色本人)。做法(v9 定稿,madoka/scripts/05): 皮肤投影位移只作采样点,
     高斯核(σ=25mm)插成**一张平滑空间形变场,皮肤/衣物/饰品查同一张场**,
     贴身衣物在皮下最近点取值(与所盖皮肤同位移→间隙构造上保持);
     **始终单张封闭网格**。两类已证伪的歧路: ①拼接原生身体网格(开放边描边锯齿);
     ②皮肤精确投影+衣物单独跟随规则(IDW 平均/表面绑定/逐点校正,三版连败:
     边界必然矛盾,破皮↔起皱拉锯)。QA 用数值: 贴身衣物间隙保持率 median 应 ≈1.00。
6. **UV 层命名 UV0** ⭐v2:图集重映射后把主 UV 层改名 **`UV0`**、删掉其它 UV 层(mmd 导入
   自带 UVMap/UV1/UV2/UV3)。GakumasMI 导出器按名字优先找 "UV0",找不到就按打分挑,
   千咲实战它挑中了 UV2(原始 MMD 坐标)→ 进游戏颜色全乱且 mod.ini 无法补救(UV 烘进 VB)。

## 1. 贴图图集(t0 baseColor)

- **多材质合一 + 正方形**(插件要求 t0/t1/t4 均为正方形):4096² 图集。
  - 简单源(秋栗,2 张贴图):左半 cloth / 右半 body,np.repeat 整数倍点放大补方。
  - 复杂源 ⭐v2(千咲,6 张 2048²):**按源贴图分格**——4096² 切 2048² 象限 + 1024² 子格,
    主贴图(皮肤/主衣)满格、次要贴图降采样进子格;每格四周留 GUARD_PX=8 保护带并
    **边缘复制填充**防双线性渗色。布局写成独立 `atlas_layout.py` 纯 python 模块,
    PIL 打图集和 Blender 重映射 UV **import 同一份数字**,永不失同步。
- **UV 仿射重映射**:每个材质的 [0,1]² UV 仿射映射进自己源贴图所在格的内缩矩形
  (v2 通用化;秋栗那种只改 U 是特例)。
- **镂空件自动分类 → native-co 双图集** ⭐v2(插件 0.7.1 支持,别再问用户透明怎么办):
  - 判据:对每个材质,在其**实际 UV 足迹**上采样源贴图 alpha,`transp% > 30%` → CO 组。
    千咲实测:Star/Cloth_ArmRing/Cloth_LegRing/Cloth_Belt=CO;Cloth_Les/Sleeve 虽用
    Alpha_D 但足迹全实心(0%)→ 留 opaque。整图统计会误判,**必须按 UV 足迹**。
  - CO 组单独打一张 **bdyco 图集**(2048² RGBA,**alpha 保留**做 cutout、RGB 外扩防黑边),
    UV 分流映射进 bdyco;opaque 组走 bdy 图集(RGB,整体 alpha-bleed)。
  - t1/t4/SDW 各出**两套**(bdy 4096² + co 2048²),烘焙时互相路由到丢弃目标避免串格(§3)。
  - 前提:目标服装抓帧配置档要有 co section(profile 里 body.section1 /
    Geo_Body.json 第二 submesh);没有就只能全 opaque。
- **肤色校准**(色差主源):游戏原版 body 贴图预览在 `research/texture-previews/<hash>.png`,
  采样其皮肤块均值作为目标;对图集皮肤半区做**线性空间逐通道比例校正**。只校 bdy 皮肤区,
  co 图集不参与。
- **肤色校准**(色差主源):游戏原版 body 贴图预览在 `research/texture-previews/<hash>.png`,
  采样其皮肤块均值作为目标;对图集皮肤半区做**线性空间逐通道比例校正**。
  - ⚠ 比例必须用「线性化像素的均值」而不是「sRGB 均值的线性化」(Jensen 不等式,
    后者会过冲导致肤色发白);对 sRGB 均值误差做 2~3 轮迭代收敛。
  - 秋栗实测:游戏肤 sRGB (0.997, 0.900, 0.864) vs 终末地肤 (0.846, 0.641, 0.621),
    线性比例 ≈ (1.74, 1.86, 1.94)。
  - 脚本:`skin_match2.py`(从源贴图重建图集+校色+重派生 SDW,幂等可重跑)。

## 2. 体型 / 姿势对齐(v1 `rebuild_all.py` / v2 `chisaki/scripts/03_align.py`)

从源 blend 只读加载、另存新文件,全程幂等,任何断言失败直接报错拒绝保存。

⭐v2 两条硬教训:
- **游戏参考模型(Geo_Body_Armature + GMI 参考体)存独立 `game_ref.blend`**,对齐脚本
  发现缺就自动 append。别让它活在管线中间产物里——上游脚本重跑会把它连锅端掉。
- **必须全骨架 retarget,不是只对手臂!** 秋栗碰巧躯干接近,千咲整个身体后仰,
  胸/脖/膝/踝相对游戏骨架偏后 26~46mm,只对手臂 = 手对了、人歪着。完整顺序:
  1. **root 锚定**:センター 平移,把左右大腿根中点压到游戏 UpLeg 中点;
  2. **脊椎直接映射**:上半身→Spine1、上半身1→Spine2、上半身2→Neck、首→頭 逐段 fit
     (试过按弧长比例插值,首 会差 20mm;直接逐关节映射全 0.0mm);
  3. **腿 FK 对齐**:先 **mute 腿上的 IK / DampedTrack / LimitRotation 约束**
     (MMD 腿是 IK 驱动,不 mute 则 FK 摆完被 IK 拽回去),再 足→UpLeg 平移吸附、
     足→ひざ→足首→つま先 逐段 fit;足D/ひざD 等变形骨靠自带 TRANSFORM 约束随动;
  4. 手臂+手指(同 v1 表 4/5 行)。
- 烘焙闸门加**网格 Y 带检查**:评估网格在膝/胸/脖三个 z 带的 Y 质心与游戏体差
  <20/30/30mm,防"骨骼对齐了、网格没跟上"再犯。

⭐v3 第三条硬教训(dress_2219 / fuyuko 实战,2026-07-25):
- **prep 会把绑定搞坏,而且静止完全看不出。** 判据:`骨到它所驱动几何(主导顶点质心)的距离 ÷ 该骨自身长度`。
  实测 `dress_2219_full_todo.blend`(原始)手指 = 16mm、`dress_2219_gakumas_work.blend`(prep 后)= **50.5mm**,
  ——网格动了、手指骨没一致跟着动,权重于是照错位骨刷,「顶点属于哪一节」整体错约 2 个指节。
- **为什么只有手指炸、四肢没事**:偏差是绝对的、骨长是相对的。手指骨节 20~25mm,偏差 50mm > 骨节本身 → 撕碎;
  手臂骨长 150~300mm,同样 30mm 偏差只占 10~20% → 只表现为轻微滑动,肉眼放过。**所以判据必须除以骨长,
  不能用绝对毫米。** 本节步骤 6 原来的「指尖 |x|max 与游戏差 <20mm」是**模型相关**判据(那个模型最外侧
  恰好是指尖);宽袖/飘带服装最外侧是袖子,该判据会量到袖子,fuyuko 就是这么漏过去的。
- **AB 路线不容错,这条比 3Dmigoto 更严**:3Dmigoto 靠逐影响 `BoneCorrections`(运行时把源 bind 空间显式
  映射到游戏空间)容忍源/游戏骨架差异;AB 是标准 LBS(`Σw·游戏骨·bindpose·v`),**没有逐影响校正**,要求
  几何本身就在游戏关节上、且权重引用的骨确实在几何内。同一个源 3Dmigoto 版能动、AB 版炸,**不是 AB 的 bug,
  是 AB 把 prep 质量要求提前了**。
- **踩过的五条弯路(都实测证伪,别再走)**:① bundle 改用源骨架 bindpose → 静止直接崩(AB 顶点已在游戏空间,
  等于重复校正);② 传递权重(整身/仅手部、反距离/重心插值两种实现)→ **更糟**(手指 edge-stretch p99 2.99→6.96);
  ③ 逐顶点乘 `gameRest·sourceRest⁻¹` retarget 几何 → 手指绕自身轴扭烂(该矩阵含 roll 差);④ pose 摆源骨到
  游戏关节再烘 → 网格反而离游戏关节更远(绑定本身错位,骨一动网格跟着跑偏);⑤「源/游戏逐骨朝向差 90~180°」
  是 Blender 骨轴约定差,**无害**(四肢同样差却正常)。**坏绑定只能回上游重做 prep,导出侧无法补救。**

| 9 | **遮挡皮肤删除**(手套等双层区) | 皮肤面「四角+中心沿法线射线 **全部**命中遮挡布料(12mm 内)」才删 → 指尖、手背开口等露肤设计自动保留,遮挡边缘保守留余量不露洞。**别用内缩/外撑间隙法**(治标,剧烈动作仍穿) |

验收标准:36 个手臂/手指关节 Δ ≤ 0.02mm;领口顶 = Head-5mm ±3mm;指尖 |x| 与游戏差 ≤ 数 mm。

## 3. 材质贴图 t1 / t4(语义以 `gakumas_mi/material_presets.json` 实测为准!)

⚠ `profiles/*/texture_map.json` 的 t4.A="shadeColorBlendStrength" 是抓帧时代旧标注,**已过时**。

| 通道 | 语义 | 布料区 | 皮肤区 | 金属件 |
|---|---|---|---|---|
| t1.R | toon 阴影阈值 | 0.38 | 0.45 | 0.34 |
| t1.G | 光滑度 | 可用源游戏 P 图 A 通道(实测≈0.40 吻合) | 0.13 | P 图 A |
| t1.B | 金属度 | 0(或 P 图 R 通道) | 0 | ≈0.75~1 |
| t1.A | AO/间接光 | **≈0** | **0** | 0.57 |
| t4.RGB | 暗面色 | `lin(base)×0.45→sRGB` | `lin(base)×0.78→sRGB` | ×0.32 |
| t4.A | **皮肤二值遮罩** | **0** | **1** | 0 |

踩过的坑(各浪费一轮进游戏验证):
- t4.A 全填 1 → 全身走皮肤二材质路径,整套衣服泛粉。
- t4.RGB 用源游戏 ramp 阴影色直接线性相乘 → ramp 线性亮度仅 0.07~0.15(vs 规范 0.45),衣服压成死黑。
- t1.A 搬源游戏白 AO(μ0.9) → 间接光拉满,袖子大片白斑。

源游戏(终末地)贴图后缀速查:`D`=漫反射 ✓ / `P`=打包遮罩(R金属 G-AO A光滑,可搬 R、A)✓ /
`RD`=阴影 ramp(只做调色参考)/ `N`法线、`E`自发光、`RS`高光 ramp、`lut`、matcap = 无对应槽位,不可用。
脚本:v1 `gen_t1_t4.py` / `verify_t1t4.py`。

⭐v2 **分材质烘焙路线**(图集按源贴图分格时必用):图集区域和材质类型不再一一对应
(如 Up_D 格里皮肤和金属混在一起),不能按区域填常量。做法(chisaki `04_bake_and_sample.py`):
- `atlas_layout.MAT_PRESET` 给每个材质标 `material_presets.json` 预设 key(skin/cloth/metal/
  leather_shoe/leather_plastic);
- Cycles 逐材质发射常量色,按 UV0 烘进图集空间的**类型图**:`type_t1rgb`(R=toon阈值
  G=光滑 B=金属)+ `type_aux`(R=AO G=t4暗系数 B=皮肤二值 mask),margin=16;
- `05_finalize` 用类型图合成 MSK/SDW,皮肤 mask 顺便当肤色校准的选区;
- **bdy/co 双图集时烘两轮**:烘 bdy 时把 CO 材质的烘焙目标指向 64² 丢弃图,反之亦然
  (两套 UV 空间重叠,不路由开会互相污染)。

## 4. DDS 输出(`make_dds.py`)

| 贴图 | 格式 | 色彩空间 |
|---|---|---|
| t0 D / t4 SDW | BC7_UNORM_SRGB 或 RGBA8 DXGI 29 | sRGB |
| t1 MSK | BC7_UNORM 或 RGBA8 DXGI 28 | **线性** |

- 无 texconv 时用插件同款格式:未压缩 RGBA8 + DX10 头、单 mip、top-down
  (等价 `gakumas_mi.core.write_rgba8_dds`,`inspect_dds` 必过;4096² 每张 67MB,显存 ≈4×BC7)。
- ⚠ t1/t4 的 **A 通道是数据遮罩不是透明度**:看图软件里显示"全透明/空图"是**正常现象**。
  严禁用图像编辑器打开另存(会漂白 A=0 处的 RGB)、严禁 texconv 加 `-pmalpha`。
- 用 texconv 时:`-f BC7_UNORM_SRGB -srgb -m 0`(D/SDW)、`-f BC7_UNORM -m 0`(MSK,无 srgb 旗标)。

## 4.5 GakumasMI 插件导出 ⭐v2(全是千咲实战踩出来的)

导出前 Blender 侧检查:
1. 网格只剩 **一个 UV 层且名为 `UV0`**(见 §0-6,这条不满足=白导)。
2. **NATIVE_CO 材质标记**:走 bdyco 的材质(千咲=Star/Cloth_ArmRing/Cloth_LegRing/
   Cloth_Belt)在材质属性里把 `渲染材质` 设为 **原生co**;其余保持 不透明。

导出面板必填:
3. **「body t0 基础色 / BaseColor」必须填**(bdy 图集 D,PNG 或 DDS 都行,PNG 会自动转)。
   漏填的后果不是报错,而是 material_textures 里没有 baseColor → **mod.ini 静默不生成
   `ps-t0`**,游戏继续用原角色底色贴图 → 颜色乱。t1/t4 同理填 MSK/SDW。
4. 有 NATIVE_CO 材质时,「原生 co / m_bdyco」区**必须填 co 的 t0**(co 图集 D,含 alpha);
   co 的 t1/t4 也填 co 那套 MSK/SDW(留空会用中性图,co 件质感全丢)。
5. **「未映射骨骼兜底」填 `Hips`**:MMD 总有几个顶点残留在控制骨/物理骨上
   (报错样式:`顶点 N 没有可导出的配置档兼容权重`),兜底后自动挂到 Hips。
   若受影响顶点多(>几十),回 Blender 把这些权重转给正确变形骨再导。

导出后核对 mod.ini / export-report.json:
- `export-report.json` 的 `uvLayers.uv0` 必须是 `UV0`(不是 UVMap/UV2!);
- mod.ini 的 TextureOverride 块里应有 `ps-t0`(+ t1/t4);
- 有 co 时应有 native co section 的 override 块(参考 `nativeCoRanges` 非空)。
