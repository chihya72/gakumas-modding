# 2. 插件负责什么

先把边界分清，后面遇到红色提示时才知道应在插件里修，还是回到建模工作。

## 2.1 输入和输出

GakumasMI 的主要输入是：

- 一个目标配置档；
- 一个已经完成基本建模、UV、骨架绑定和权重的作者网格；
- 一套正方形游戏贴图；
- 一个装着 R32 模板的 `templates` 目录。

最终输出是一个 Mod 目录，其中至少有：

```text
<mod-id>\
  <mod-id>.bundle
  mod.json
  bundle-src\
```

`bundle-src` 是诊断与重新打包所需的中间产物。安装时复制整个 `<mod-id>` 目录，不要只复制 `.bundle`。

## 2.2 配置档与参考模型

配置档记录“替换谁”和“怎样把数据写回目标资源”。第一次替换某个目标时，由抓帧与 JSON 资源库生成；以后可以直接复用。

阶段 1 导入的原版网格和骨架是参考资料，用于：

- 对齐作者模型的位置、姿势和尺寸；
- 读取目标肤色和部分顶点数据；
- 骨名匹配与导出体检。

参考模型不是最终作者网格，也不是权重来源。不要删掉它，直到 Mod 已完成导出和实机验证。

## 2.3 作者模型

作者模型是你真正要放进游戏的网格。它必须已经具备：

- 有效材质槽；
- 活动 UV；
- Armature 修改器；
- 顶点组权重；
- 与参考骨架对齐的静止姿势；
- 已应用的对象旋转与缩放。

插件能检测这些项目是否存在，但不能判断造型是否正确、头部是否删干净、衣服是否穿模，也不能自动修好错误绑定。

## 2.4 骨名映射，不是传权

AssetBundle 路线保留作者模型的权重分布。插件把作者顶点组所引用的源骨，映射到游戏骨或转换为明确的装饰骨策略。不存在“从参考身体把权重传给作者模型”这一步。

这意味着：

- 权重画得不好，插件不会替你重画；
- 常见骨架命名会被预设自动识别；
- 无法自动决定的骨必须在阶段 4 逐组处理；
- body 导出会检查 21 个关键承重关节是否拿到了权重；
- 每个顶点导出后最多保留 4 个骨影响，超过部分会被截断并重新归一化。

## 2.5 body、hair 与 hairprop

面板顶层制作目标只有：

- `身体（body）`：服装与身体主体；
- `发型（hair）`：发型主体，可同时带一个配套发饰。

`hairprop` 不是独立制作目标。要替换发饰时，在 hair 项目的 `配套发饰（可选）` 或 `发饰对象` 中选择它，最后与 hair 一次导出。

## 2.6 t0、t1、t4

| 贴图 | 作用 | 最低要求 |
|---|---|---|
| t0 | 基础色，body 与 hair 的最终颜色来源 | 必填，正方形 |
| t1 | 阴影阈值、光滑度、金属度和分部件数据 | 可提供；否则由插件按材质生成 |
| t4 | 暗面颜色，不是投影阴影贴图 | 可提供；否则由插件按材质生成 |

t1 和 t4 的 Alpha 通道是数据，不应按普通透明度理解。没有自制 t1、t4 时保持 `中性 t1/t4` 开启，再使用 `生成游戏材质贴图`。

## 2.7 模板、打包器与 Runtime

三者职责不同：

- R32 模板提供与目标资源相同的 AssetBundle 外壳，插件按目标资源名从模板目录里取；
- UnityPy 把作者数据写入模板；
- Gakumas Mod Runtime 在游戏里读取 `mod.json`、加载 bundle 并替换目标。

制作工具发布包不包含游戏 Runtime。能够在 Blender 导出成功，不代表游戏端已经安装或版本兼容；实机问题先确认 Runtime 和 `gakumas-mod\mod-plugin.log`。
