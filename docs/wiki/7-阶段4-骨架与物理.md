# 7. 阶段 4：骨架与物理

这一阶段不重画作者权重，而是为每组带权重源骨确定最终去向。身体骨映射到游戏骨；装饰骨选择合并、跟随、自建物理、烘焙或拒绝。

## 7.1 建立处理队列

点击 `扫描源骨骼`。默认扫描会：

1. 读取作者网格上实际带权重的顶点组；
2. 套用常见骨架命名预设；
3. 预设认不出必需的人形骨时，改按骨架结构识别（见 7.2）；
4. 把结构上同一条装饰链合并成一行；
5. 只列出不能自动收口，或以前已手动处理过的行。

因此队列不是完整骨架清单。要审计所有骨时点击 `列出全部`；日常制作使用 `重新扫描待处理`。

重新扫描会保留已经填写的映射、装饰策略和部件类型。`清空` 只清队列，不删除作者网格的骨和权重。

未决定的行很多时，打开红色汇总行右侧的 `只看这些`，列表会暂时隐藏已经收口的骨组。

## 7.2 一行怎样处理

先在列表选择一行，再看下面的 `选中骨组的处理方式`。

面板上有两栏，分工不同：

- `自动判定`：只读，显示插件自己算出来的目标骨，以及它是怎么来的。每次扫描都会重算。
- `覆盖为`：只在你要推翻自动判定时才填。填了它，下面的装饰选项就会隐藏。

身体骨通常由 `自动判定` 直接填好，不用动。`自动判定` 后面会标出来路：

| 标注 | 含义 |
|---|---|
| 来自预设 | 骨名命中了已知骨架命名（MMD、mixamo、rigify 等） |
| 按骨架结构推断 | 骨名不认识，见下方说明 |
| 按位置匹配 | 装饰骨按空间位置找到的最近目标 |
| 逐骨不同 | 这一组里各骨的自动判定不一样，`拆成逐根处理` 后可分别查看 |

### 骨名不认识时

骨架命名太特殊、预设一个都对不上时，插件会改用**骨架结构**来识别：人体只有一种拓扑，
从骨架自己量出上下和左右，再按连接关系认出胯、脊椎、手臂、腿、锁骨和头。这一档只认建立
人形角色所必需的那些骨，手指不参与。

这样认出来的行标着 `按骨架结构推断`，并且**不会被折叠**——它是按形状推的，请自己过一遍。
认错了就在 `覆盖为` 里手动指定，手填的覆盖压过自动判定；点右边的 ✕ 清掉覆盖可以回到自动判定。

必需骨认不齐时，插件不会只填一半，整批都留空交给你手填。

### 装饰骨

如果它不是身体骨，`覆盖为` 保持为空，并在 `装饰处理` 中作出明确决定：

| 处理方式 | 实际行为 | 适用情况 |
|---|---|---|
| 自动 | 尚未形成明确决定；未被预设处理时仍会标红 | 不要把红色自动项留到成品导出 |
| 刚性跟父骨 | 合并到最近的已映射身体父骨，不增加物理 | 硬扣、徽章、不确定的静态附件 |
| 自建摇物链 | 保留或创建装饰骨，并生成自己的摆动物理 | 飘带、蝴蝶结、独立悬垂链 |
| 跟裙摆 | 合并到最近的目标裙摆摇物骨，不受普通距离回退限制 | 必须与原版裙摆同步的裙边 |
| 跟随最近骨骼 | 跟最近目标摇物骨；超过安全距离时回退为刚性父骨 | 靠近现有摇物结构的小附件 |
| 原版布料驱动器 | 新建骨并使用游戏布料驱动器 | 裙、披挂、袖三类 |
| 烘焙形变+并到父骨 | 把该骨造成的静止偏移烘进网格，再合并到父骨 | 不能直接合并、但不需要运动的静态件 |
| 拒绝导出 | 明确声明当前无法安全处理，并阻止导出 | 需要回建模阶段重做的骨 |

队列把一条结构链合为一组，是为了减少重复选择。组内骨需要不同目标或策略时，点击 `拆成逐根处理`。`查看这组权重` 用于在 3D 视图确认这行实际控制哪些几何。

## 7.3 自建摇物链

选择 `自建摇物链` 后需要设置 `部件类型`：

- `自动`：按骨名判断，无法识别时按飘带处理；
- `飘带 / 蝴蝶结`：自由悬垂；
- `披风 / 褶边 / 领腰`：使用较轻的链参数；
- `袖口`：使用限位较紧的袖类参数；
- `裙 / 裤 / 外套下摆`：使用裙类链和碰撞。

部件类型决定参数来源，不会修正错误的骨层级、枢轴或权重。

### 链根自己摆

有些短链的全部主导权重都在链根，子骨没有实际控制几何。对于 `自建摇物链`，默认链根是锚点；如果几何只在根上，游戏里看起来就不会动。

只有该行出现红色提示时才处理：

- 希望链根本身运动：打开该行的 `链根自己摆`；
- 希望根固定、子骨运动：回 Blender，把需要摆动区域的权重分给子骨。

不要给所有链统一打开。链根是否应运动取决于具体几何。

## 7.4 原版布料驱动器

这条路线只实现三种通用驱动器：

| 部件类型 | 驱动器 | 通用参考骨 |
|---|---|---|
| 裙类 | Skirt | 左右大腿 |
| 披挂类 | Frill | 左右手臂 |
| 袖类 | HumanoidSleeve | 左右手 |

飘带没有对应的原版布料驱动器，应改用自建摇物链。选择了不支持的类别时，该行会标红并阻止导出。

## 7.5 对齐体检

处理队列后点击 `量对齐与跨关节权重带`。它只测量，不改模型，报告包括：

- 逐骨静止方向差和关节位置差；
- 各类权重最终去了直接映射、合并、辅助骨、烘焙或未决定中的哪一类；
- 多根源骨塌到同一目标骨的链；
- 肩、肘、腕、膝的跨关节权重带与原版参考值。

方向差和跨关节带不能靠一张静止截图判断。报告中的异常应回 Blender 验证动作；尤其肩部跨关节权重明显低于参考值时，只能补作者权重，导出器无法修复。

## 7.6 修复工具

`修复工具（会改模型）` 默认折叠，因为这两类操作不属于每个项目的必经步骤。

### 从相邻骨劈权重

只在 body 源模型根本没有锁骨、脖子、脚尖等关键承重关节时使用。它参考原版身体同一位置的权重分布，从相邻作者骨中分出缺失关节权重。作者模型必须先与参考骨架对齐。

如果源模型本来有该关节，只是骨名没识别，应当补映射，不要劈权重。

### 烘焙静止形变

选了 `烘焙形变+并到父骨` 后，必须点击 `烘焙静止形变` 才能导出。插件会在修改顶点前把原始坐标记录在对象上：

- 已经烘过一次时，不能连续叠加；
- `回退烘焙` 可以恢复记录中的原坐标；
- 回退后要重新烘焙，阶段 5 才会放行。

## 7.7 哪些情况一定会阻止导出

先是几何本身的问题，它们和骨名、参数都无关，但一错就整个包报废：

- 网格面朝里（法线整体翻转）；
- 左右装反；
- 并进游戏衣物骨、子骨却还留在自己骨架里，整支子树会被外来物理拽走；
- 有骨的静止朝向与游戏骨差得太多（≥45°）——静止截图看着正常，转身之后才炸。

再是骨的去向：

- 仍有未决定的骨组；
- 某组被标为拒绝导出；
- 烘焙策略尚未执行；
- 自建骨与游戏骨架里已有的骨重名；
- body 的关键承重关节没有任何源权重；
- 有带权重源骨既没有目标，也没有可执行的装饰策略；
- 自建链的权重全在链根，但没有决定让链根运动或重画权重；
- 原版布料驱动器选择了不支持的部件类型。

最后两条由界面拦住（导出按钮会保持禁用）。

高级区的 JSON 映射文件与队列表达同一类决定。队列里手动填写的内容优先。普通作者项目不需要维护外部映射文件。
