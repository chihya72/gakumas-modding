# 8. 阶段 5：检查与导出

这一阶段集中显示前四个阶段的阻断项，并在全部清空后生成可安装的 AssetBundle Mod。

## 8.1 模组信息

| 字段 | 用途 |
|---|---|
| 模组标识 | 唯一 ID，同时成为目录名和 bundle 文件名 |
| 模组名称 | 游戏内 Mod 管理页面显示的名称 |
| 作者 | 游戏内显示的作者名 |

模组标识建议只用小写英文字母、数字、点和横线，例如：

```text
author.hski.my-costume
```

导出器会自动转小写，把空格和下划线改成横线，并清理其他字符；不要依赖自动清理来区分两个 Mod。同一标识会写入同一输出目录，游戏端也会把它们视为同一个 Mod。

## 8.2 成品位置与模板

`输出目录` 是成品包的父目录。若模组标识为 `author.hski.my-costume`，成品会写到：

```text
<输出目录>\author.hski.my-costume\
  author.hski.my-costume.bundle
  mod.json
  bundle-src\
```

`R32 模板 bundle` 必须与阶段 1 的目标资源对应。例如目标是 `mdl_chr_atbm-cstm-0140_body`，就选择 `template_mdl_chr_atbm-cstm-0140_body.bundle`。模板属于目标，不属于作者模型。

hair 项目会在这里再次显示 `发饰对象`。它与阶段 2 是同一个字段，用于把 Geo_HairProp 合并进同一个包。

## 8.3 外部 Python

只有插件找不到内置 `vendor\UnityPy` 和 Pillow 时，界面才显示 `外部 Python`。当前公开的 GakumasMI 轻量包会显示该字段。

验证当前 Python：

```powershell
<python.exe> -c "import UnityPy, PIL; print(UnityPy.__version__)"
```

应输出 `1.10.18`。没有安装时执行：

```powershell
<python.exe> -m pip install UnityPy==1.10.18 Pillow
```

字段可以填 `python`，也可以填实际 `python.exe` 绝对路径。不能使用 Blender 自带 Python。

## 8.4 导出前检查

主按钮上方会列出当前已知问题。典型返回路径：

| 提示 | 返回哪里 |
|---|---|
| 缺少配置档 | 阶段 1 |
| 作者模型、UV、材质槽、Armature、变换有问题 | 阶段 2 |
| 缺少 t0 或原生 co 贴图 | 阶段 3 |
| 骨组未决定、拒绝、策略无效或未烘焙 | 阶段 4 |
| 输出目录、标识或模板为空 | 本阶段 |

界面没有发现明显阻断时，`导出并打包 bundle` 才会启用。点击后仍会执行更完整的硬闸门，按先后顺序是：

- 网格是否面朝里；
- 是否有子树被并到游戏衣物骨、子骨却留在自己骨架里；
- 左右是否装反；
- body 关键承重关节覆盖；
- 是否有骨被标为拒绝导出，或标了烘焙却没烘；
- 自建骨是否与目标骨架重名；
- 静止朝向是否有骨差到红档；
- 所有带权重源骨是否有去向；
- 每组材质能否归并到模板允许的段数；
- 模板、贴图和外部打包器是否实际可读。

顺序不是随意排的：前三条是几何事实，它们一错，后面所有关于骨和权重的数字都会跟着错，
先报出来才不会让人去改错的地方。

有几类问题只提醒、不拦：自建摇物链上没有带权重骨（白建一条，不损坏包），以及跨骨族下物理
指令。它们出现在状态栏，值得看一眼，但不影响出包。

因此按钮可点击不等于必然成功。最终错误信息来自实际导出和模板补丁，应按它点名的对象或文件处理。

## 8.5 正常导出

点击 `导出并打包 bundle`。成功提示会同时给出 `.bundle` 和 `mod.json` 路径。

中间的 `bundle-src` 包含导出的 geojson、骨架 sidecar、贴图和打包清单。它用于诊断和重新打包，不要在问题尚未解决前删除。

作者权重中每顶点超过 4 个骨影响时，导出器会截掉第 5 个起的影响并重新归一化。如果状态栏出现截断权重警告，应回 Blender 把相关顶点限制到 4 个有效影响，再重新导出。

## 8.6 安装和启用

把整个成品目录复制到：

```text
<游戏目录>\gakumas-mod\mods\<mod-id>\
```

目录内必须同时保留 `mod.json` 和同次导出的 `.bundle`。启动游戏后，在游戏内 `Mod 管理` 页面启用。相同目标的多个 Mod 不能同时启用。

运行时日志位置：

```text
<游戏目录>\gakumas-mod\mod-plugin.log
```

默认日志级别为 `error`。需要完整替换过程时，在 `gakumas-mod\config.json` 使用：

```json
{
  "modManagerUi": true,
  "logLevel": "info"
}
```

排查完建议恢复 `error`。

## 8.7 诊断和风险放行

`只导出 bundle 源（诊断）` 只生成中间文件，不得到可安装 `.bundle`。它用于区分“Blender 数据导出失败”和“UnityPy 模板补丁失败”。正常制作不走这条路线。

`高级 / 风险放行` 包含：

- `允许未决定的骨导出`；
- `未映射骨兜底`。

它们用于定位问题，不是成品流程。放行未决定骨会在 sidecar 和权重报告中留痕，但不能保证几何跟对骨；使用兜底则可能把整块几何并到错误关节。准备发布的 Mod 应回阶段 4 把每组骨处理清楚。
