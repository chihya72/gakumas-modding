# 7. 发型与发饰

发型 mod 和 body mod 走同一套三步 UI，但有几个关键差异必须先搞清楚，否则会做错。

## 7.1 一个核心事实：发型 = 发型 + 发饰两个部件

**游戏内只有「发型」选择，没有单独的发饰选择。** 每个 `mdl_chr_*_hair` 资源包同时含：

- **发型网格 `Geo_Hair`** —— 发丝主体；
- **配套发饰网格 `Geo_HairProp`** —— 发夹 / 蝴蝶结 / 花饰等。

装备发型时两者一起显示，但由**同一套三步 UI** 管理。

> **顶层始终只选择「发型」。** 插件自动导入 / 处理 `Geo_HairProp` 并记录精确 selector。作者可以只替换发型，也可以同时提供发饰网格。**不再把发型和发饰当作两个制作目标。**

两个 JSON 资源都来自同一批 `_hair` 包：
```powershell
# 导出时分别指定 mesh 名
--mesh-name Geo_Hair
--mesh-name Geo_HairProp
```

> 📷 **待截图**：`images/hair-two-parts.png` —— 一顶发型拆成 Geo_Hair（发丝）+ Geo_HairProp（发饰）的示意。

## 7.2 制作目标设为「发型（hair）」

流程和 body 一样走 ①②③，只是：

- 步骤① 的 `网格 JSON 资源库` 要指向 hair 库（同时含 `Geo_Hair` 与 `Geo_HairProp`）；
- 步骤② 的贴图语义与 body 不同（见 7.3），发饰另有三栏自己的贴图（见 7.4）；
- 步骤③ 只有发型网格时导出只替换 `Geo_Hair` 保留原发饰；有发饰网格时合并成一个包。

> **承重关节闸门对发型永不触发**——14 个关节与发型骨架的交集为 0，所以发型导出不会被它拦。

## 7.3 配套发饰：自带权重即可，没有「绑定」这一步了

**0.9.0 起插件不做任何权重操作。** 旧版那两个按钮 `刚体绑定到 Head_Hair` 和
`传递发饰权重` 随 3DMigoto 路线一起删了。现在的规则很简单：

- **发饰网格自带什么权重，就用什么权重**；
- 硬质发饰（发夹、硬花）在建模软件里把全部顶点刷 `Head_Hair = 1.0` 即可，效果和旧版
  「刚体绑定」一样，只是这一步挪到了你自己手上；
- 要摆动的软发饰（缎带等）自己刷好权重，骨名认不出来时去步骤③的骨骼映射表点选，
  或给它选「自建摇物链」策略。

导出规则：

- 只有发型网格 → 导出只替换 `Geo_Hair`，保留原发饰，用 hairprop 特征精确限定目标；
- 同时有发饰网格 → 点一次 `导出并打包 bundle（一键，需外部 Python）` 自动合并成一个完整包；
- **发型与发饰是一个包，不存在分开启用。** 游戏内 Mod 管理里一个发型 mod 就是一行开关。

## 7.4 Hair 的贴图 / 顶点色语义（≠ body）

hair 与 body 共用主光照框架，但作者规则不同。制作目标选「发型」后插件用以下**安全默认值**：

### t0.A 是刘海 Coverage，不是普通透明度

- `A=0`：头发主体不透明，眉眼不能透过刘海；
- `A>0`：允许视角相关的发丝覆盖，眉眼在适当区域透出；
- 0.7.8 默认**保留作者 Alpha**；需要禁用时关掉「使用 t0.A 发丝覆盖率」；
- `Hair21_D.png` 这类需要眉眼透出的图应保持开启，但最好后续把 Alpha 改成只覆盖前额 / 眉眼区域；
- **不要把「普通 PNG 默认 A=255」误当原版 coverage mask。** 通用发型不应盲目把所有区域设 255。

### t1 PackedMask

R=toon 阈值、G=光滑度、B=金属度、A=镜面 / 间接 / HHL 门控。当前插件**不替换 t6 发丝高光图**，所以自定义 UV 用 **A=0** 屏蔽旧 HHL。安全中性预设 `(67,32,0,0)`。

> ⚠️ t1.A 写高 → 换过 UV 的新发型可能错采原角色 t6，产生蓝紫色斑纹或旧发色泄漏。

### t4 ShadeColor

RGB 是独立的作者暗面颜色，A 在两套暗面公式间选择（hair 通常为 0）。缺 t4 时插件用线性冷阴影乘数 `(0.378,0.367,0.474)` 作 fallback（安全预设，非固定公式）。

### 顶点色 COLOR：按发色明度选描边档

原版支持按发片变化的描边色；插件对新拓扑采用**全网格常量安全档**。导出面板按发色明度选「发型描边色档」：

| 发色 | 描边档 |
|---|---|
| 深色发 | `(0,0,1)` |
| 粉红发 | `(1,0,0)` |
| 金浅色发 | `(4,2,1)` |
| 纯黑 | `(0,0,0)` |

**宁小勿大（描边宁暗勿亮）。** 精确字段（`G低=t7 LUT 行`、`B低=描边宽度`、`A高=边缘 mask`）由插件从带权重参考网格最近邻拷贝——**导出 hair 时必须保留参考模型**。

## 7.5 发饰（HairProp）的贴图与顶点色

### 贴图必须按发饰自己的 UV 做

步骤②面板里，发饰有自己独立的一组三栏（在「发饰贴图（只在制作发饰时填写）」小框里）：

| 面板上的字 | 对应 |
|---|---|
| `发饰基础色 t0` | 发饰的 BaseColor |
| `发饰混合遮罩 t1` | 发饰的 PackedMask，A 门控镜面/间接光，安全预设为 0 |
| `发饰暗面材质 t4/sdw` | 发饰的 ShadeColor |

只有在同时替换 `Geo_HairProp` 时才填这三栏：

- Hair 做了、HairProp 没做 → 发饰三项**全部留空**，游戏保留原发饰；
- HairProp 做了 → 三项都填，**至少必须有发饰 t0**，否则颜色沿用原发饰；
- **发饰贴图不能复用 Hair 的 UV atlas**，必须按发饰自己的 UV 制作。

### 发饰顶点色：按材质槽写常量（不走参考拷贝）

发饰几何与参考不重叠，改为按材质槽的「材质类型」写常量（原版实测）：

- `metal` → 灰描边 `(3,3,3)` + A高 rim mask 9/15；
- 其余类型 → 黑描边 `(0,0,0)` + A高 0；
- 宽度 B低统一 8。

金属件把材质槽类型标 `metal`；亮色布件（白花等）想要灰描边也可标 metal。

> ⚠️ 暗环境下 metal 预设的高金属度会让小饰品发乌（混入环境立方图），**饰品的 t1 建议用布料参数**。

## 7.6 分别烘焙，互不覆盖

Hair 与 HairProp 的「按材质生成 t1/t4」必须**分别激活对应作者网格**执行。0.7.7 起两者用独立临时文件名，不会因后烘焙发饰而覆盖已生成的 Hair PackedMask / ShadeColor。

贴图输入的完整字段说明见 [[5-步骤②-材质与贴图]]。
