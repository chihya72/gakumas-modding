# 11. 常见问题与排错

先按症状找，不要同时改模型、贴图、模板和 Runtime。每次只验证一个假设。

## 11.1 面板不是五阶段中文界面

安装的是旧插件，或 Blender 内存中仍加载旧模块。

处理：

1. 在偏好设置中卸载旧 GakumasMI；
2. 关闭所有 Blender 窗口；
3. 重新打开 Blender；
4. 从磁盘安装当前 `gakumas_mi-<版本>.zip`。

面板标题应显示与所装 ZIP 一致的版本号，顶部应有 `1 目标` 到 `5 导出`。

## 11.2 阶段 1 导入了错误参考模型

自动匹配只拿到了多个相似候选。

处理：在 `目标 body 资源（可选）` 或 `目标 hair 资源（可选）` 填完整资源名后重新生成。仍错误时打开高级区，填抓帧对应的 `主 Draw` 编号。

不要继续用错误参考做对齐；配置档、模板和最终目标会互相不一致。

## 11.3 生成游戏材质贴图提示 t0 不能读取

`生成游戏材质贴图` 需要 Blender 能读取像素，因此基础色必须使用正方形 PNG。DDS 可以作为已有导出贴图来源，但不能作为这一步派生 t1、t4 的输入。

处理：把 t0 转为正方形 PNG，再运行生成按钮。

## 11.4 游戏里没有描边

body、hair 和 hairprop 的原因不同：

- body：阶段 3 选择 `取自基础色`、`按材质预设` 或 `黑色常量`，并保持描边宽度不是关闭；
- body 使用 `沿用源模型顶点色`：确认网格存在名为 `COLOR`、域为 `POINT` 的属性；
- hair：保留阶段 1 导入的带权重 hair 参考网格及其 COLOR；
- hairprop：确认材质类型正确，插件会按槽生成安全常量。

如果只在局部没有描边，检查该区域是否进入 `GMI_NO_OUTLINE`，以及宽度是否选择 `仅安全顶点`。

## 11.5 暗面出现原服装图案

只替换了 t0，t4 仍在使用目标服装旧 UV 数据。

处理：在阶段 3 使用 `生成游戏材质贴图` 生成与新 atlas 同 UV 的 t4，或提供自己的 t4。不要把屏幕阴影截图当作 t4。

## 11.6 脖子有明显色差

通常是皮肤材质没有标成皮肤，或关闭了 `肤色对齐原版`。

处理：确认皮肤面属于正确材质槽，把槽标为皮肤，重新从原始 t0 生成。插件会另存校色结果，不修改源图。

## 11.7 hair 出现蓝紫斑纹或旧发色高光

自定义 hair UV 仍允许读取目标 hair 的旧 HHL，高光贴图落到了错误位置。

处理：使用插件生成的 hair 中性 t1，或确保 t1.A 为 0。当前插件不替换 hair t6。

## 11.8 提示有骨组未决定

这一行没有目标骨，装饰处理仍是 `自动`，因此没有形成可执行决定。

处理：

- 身体骨在 `覆盖为` 里手动指定目标骨；
- 硬附件选 `刚性跟父骨`；
- 裙边、邻近摇物或独立链选择对应策略；
- 无法安全处理时保留 `拒绝导出` 并回建模阶段修。

`允许未决定的骨导出` 只是诊断放行，可能把几何并到错误骨，不应发布。

## 11.9 自建摇物链完全不动

先在阶段 4 选中该组并点击 `查看这组权重`。如果全部主导权重都在链根，默认锚点不会自己摆。

处理：打开该行的 `链根自己摆`，或回 Blender 把需要运动的区域分权给子骨。只对出现此问题的链使用开关。

新骨和物理组件在角色资源初始化时注册。更换含新链的 Mod 后，需要重新进入角色场景；只在管理页热开关不一定重建结构。

## 11.10 原版布料驱动器被标红

当前只支持裙、披挂和袖三类，分别使用 Skirt、Frill 和 HumanoidSleeve。飘带或无法判断左右参考骨的链不能使用这条路线。

处理：改成受支持的部件类型，或改用自建摇物链、跟随或刚性父骨。

## 11.11 导出提示关键承重关节没有权重

插件检查 body 目标中的 21 个关键关节。两种原因要分开：

- 源模型有该骨，只是名字没识别：在队列映射到被点名的游戏骨；
- 源模型根本没有该关节：模型已对齐后，使用 `从相邻骨劈权重`，再重新扫描和体检。

不要把所有缺失骨兜底到 Hips 或 Spine，这会让整块几何跟错关节。

## 11.12 模型静止正常，动作时关节撕裂

这是作者绑定问题，不是模板问题。重点检查肩、肘、腕、髋、膝和手指：

- 骨是否真正位于它驱动的几何中；
- 全身是否与参考骨架对齐，而不是只对脚底或手腕；
- 权重是否跨过关节形成合理混合带；
- 每顶点是否超过 4 个有效影响。

阶段 4 的对齐体检是尺子，不会自动修权重。坏绑定必须回 Blender。

## 11.13 进游戏错位、沉地或朝向错误

作者模型没有与参考网格处于同一空间，或对象旋转、缩放未应用。

处理：回阶段 2，对齐参考骨架的全身位置和 T-pose，确认尺寸后执行 `Ctrl+A > 旋转` 与 `Ctrl+A > 缩放`，再重新导出。

不要用左右镜像来纠正朝向。正常导入的模型左右本来就是对的；如果导出被「左右装反」闸门拦下，说明源模型在别处被镜像过，回未镜像的版本重做。

## 11.14 模板补丁报 submesh count changed

作者材质槽没有归并到目标允许的材质段。常见原因是多个槽仍使用不同贴图，或把原生 co 用在只有一个普通材质段的目标上。

处理：把同一路线的材质整理到共同 atlas；原生 co 还必须选择含 m_bdyco 的目标 profile 和模板。

## 11.15 原生 co 边缘发黑或变成实心

- 边缘发黑：透明区 RGB 没有外扩，只剩纯黑；
- 变成实心：材质仍是 `不透明`，或 Alpha 没进入独立 co t0；
- 导出报缺 t0：原生 co 不会借用普通 body t0。

完整要求见 [[透明材质|10-透明材质]]。

## 11.16 自建半透明在游戏中不可用

这条路线仍在独立分支上探索，没有作为发布路线交付，也没有完成实机验收。Blender 里能选择和导出，不等于它是一条可发布的路线。

公开交付请改用不透明或原生 co。

## 11.17 hair 只替换了一半

只导出了一个 Renderer。

处理：以 hair 为 `作者模型`，在 `发饰对象` 选择 hairprop，然后一次导出。只想换 hair 时发饰留空是正确行为，原发饰会保留。

不要激活 hairprop 单独导出；插件会拒绝这种半包。

## 11.18 找不到 Python、UnityPy 或 Pillow

在系统终端用面板中同一个解释器执行：

```powershell
<python.exe> -c "import UnityPy, PIL, sys; print(UnityPy.__version__, sys.executable)"
```

应显示 `1.10.18` 和预期路径。失败时执行：

```powershell
<python.exe> -m pip install UnityPy==1.10.18 Pillow
```

如果路径是 `WindowsApps\python.exe`，安装真正的 Python 并填绝对路径。

## 11.19 Mod 没有被 Runtime 加载

确认目录结构：

```text
<游戏目录>\gakumas-mod\mods\<mod-id>\
  mod.json
  <mod-id>.bundle
```

再检查：

- `xinput1_3.dll` 是否位于 `gakumas.exe` 同级；
- `mod-plugin.log` 是否有新的 `[BOOT]`；
- 游戏内 Mod 管理是否启用该项；
- 是否有另一个 Mod 占用相同目标；
- `mod.json` 与 bundle 是否来自同一次导出。

需要完整过程时把 `config.json` 的 `logLevel` 临时设为 `info`。没有 `[BOOT]` 表示 Runtime 根本未加载，不应继续查 Blender。

仍无法定位时，保留 `.blend`、完整配置档、`bundle-src`、成品目录和 `mod-plugin.log`，并说明复现步骤。
