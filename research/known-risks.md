# GakumasMI 制作工具已知风险与排查索引

更新：2026-08-12
适用：`gakumas-modding` 1.1.0 之后的当前工作树

这是本仓库 Blender 插件、离线工具和制作流程独立审计的**唯一长期台账**。遇到导入、烘焙、
导出或一键打包异常时，先按本文的现象和 ID 排查。临时 `audit-findings.md` 只是过程稿，不再作为
事实来源。

本文只记录 `gakumas-modding` 仓库自身的问题，不记录游戏 Runtime 或 Runtime 管理器问题。
为便于从审计历史反查，继续保留原始 P 编号；未出现的编号不属于本仓库台账。除 P11 已修复外，
其余条目按当前决定只记录，不表示计划立即修改。

## 当前总体结论

1. **当前标准制作流程没有已知必现阻断问题。** 发布 ZIP 安装、三步面板、身体/发型制作、材质
   烘焙和 bundle 导出均已有真实 Blender 或成品证据；现有 7 个成品已进游戏验证。
2. **不能把所有剩余条目都叫作“小概率随机 bug”。** P10、P12 等问题有明确触发条件；只要执行
   对应操作就会确定发生，但可以通过不使用该输入或操作直接避免。
3. **P3、P4、P7 依赖特殊或异常输入。** 坏 skeleton 会让导出报错；贴边 UV 可能产生扩边接缝；
   混合颜色尺度可能生成错误顶点色。它们不会让正常输入无缘无故随机失败。
4. **P1、P2、P6、P8、P9、P13 主要影响 Blender 会话、性能或维护性，**不影响已经正确打包
   的游戏 mod。
5. **P11 已修复，不再算当前缺陷。** 外部 Python 已强制 UTF-8、非法字节安全替换并设置 10 分钟
   超时；pytest 和 Blender 4.2.7/4.5.3 的真实 bundle 打包闭环均通过。

因此，本仓当前可以继续正常制作和导出。未知新问题先查本文；命中条目触发条件后再决定是否修复，
不能仅凭一次成功断言条目不存在，也不能把仅影响另一个仓库的问题混进本台账。

## 先查：按现象排查

| 现象 | 优先检查 |
|---|---|
| Blender 一键打包卡住或中文报错乱码 | P11（已修；先确认安装的是含修复的新插件包） |
| 手写 `follow:<骨名>` 后再次保存丢失 | P10 |

| FrameAnalysis 很大时配置档检查明显变慢 | P8 |
| 禁用、重新启用插件后 Scene 属性残留 | P1、P2 |

## 表单与外部进程

### P10 `follow:<骨名>` 表单往返丢失

- 普通用户只使用表单时几乎不会遇到，因为表单不能创建这种策略；
- JSON 已存在 `follow:<骨名>`，再执行「从 JSON 读入 → 用表单保存」时，该条确定丢失，不是
  随机概率；
- 最终导出的配置不再保留指定跟随骨，饰品可能跟错位置或动作漂移。

状态：**仅记录**。需要使用时不要让该 JSON 再经过当前表单保存。

### P11 外部 Python 无超时、编码随系统代码页

旧实现可能让 Blender 无限等待外部 Python，或用系统代码页解码 UTF-8 中文输出而掩盖真实异常。
2026-08-12 已修复：外部 Python 使用 UTF-8 模式，父进程固定 UTF-8 解码并替换非法字节，且有
10 分钟超时。pytest、Blender 4.2.7 和 Blender 4.5.3 的真实打包闭环均通过。

状态：**已修复，保留作回归排查入口**。

## 制作工具已知风险

| ID | 等级 | 触发条件与影响 | 当前决定 |
|---|---|---|---|
| P1 | 中/编辑器 | `unregister()` 漏删 `Scene.gmi_physics_override_file`；同一 Blender 会话禁用插件后属性残留 | 仅记录；不影响已打包 mod |
| P2 | 低/维护 | `unregister()` 尝试删除从未注册的 `gmi_material_shade` | 仅记录 |
| P3 | 低/导出 | `_bundle_geojson` 未先验证每个 `weightedIndex` 是否落在 bindpose 范围；坏 skeleton 会抛 `IndexError`，错误信息不友好 | 仅记录；不会生成坏包继续进入游戏 |
| P4 | 低/画面 | 贴图 dilation 使用 `np.roll`，会跨图像边界环绕；UV 岛贴边时可能出现另一侧颜色细缝 | 仅记录 |
| P6 | 中/维护 | 插件仍带约 150 行退役 3DMigoto 路线死代码，部分只被旧契约测试引用 | 仅记录；不影响当前 AB 路线 |
| P7 | 低/画面 | `read_weighted_reference` 只用第一个顶点判断颜色是 0–1 还是 0–255；混合尺度异常输入会产生错误顶点色 | 仅记录 |
| P8 | 低/性能 | profile 检查对每个 binding/贴图反复递归遍历 FrameAnalysis 目录，目录很大时 Blender 操作变慢 | 仅记录 |
| P9 | 低/维护 | `_texture_semantic(..., bindings=None)` 的 `bindings` 参数未使用 | 仅记录 |
| P10 | 中/编辑器 | `follow:<骨名>` 经过表单读写会被静默丢掉；详见上方专节 | 仅记录 |
| P11 | 中/编辑器 | 外部 Python 曾无超时且输出编码不固定，可能让 Blender 永久等待或掩盖真实异常 | 已修复并测试 |
| P12 | 低/编辑器 | 只有分类、没有物理策略时，保存 JSON 不回填文件路径；下次会话不能自动读回，分类可能丢失 | 仅记录 |
| P13 | 低/维护 | `_synthesize_export_native_colors` 的 `profile_dir/component_id` 参数未使用 | 仅记录 |

## 使用与维护规则

1. 未知导入、烘焙、导出或打包问题先按现象查本文 ID，再查源码和 Blender 控制台输出。
2. 若输入来自手写 JSON、第三方 skeleton 或混合来源顶点色，优先检查 P3、P7、P10、P12。
3. 新发现只在本文增加条目或更新状态；不要把临时 scratchpad 或聊天结论当成长效台账。
4. 若修复某项，保留条目并标注修复提交、测试范围和是否有真实 Blender/成品证据。
