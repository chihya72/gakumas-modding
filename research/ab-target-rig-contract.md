## 1. 骨架契约

1. 学马 70 根人体骨的**名称、层级、静止变换、根骨**不可修改；
2. **mod mesh 的 bindpose 必须等于对应学马骨静止世界矩阵的逆**（renderer 空间）；
3. Renderer 的 `bones[]` 顺序与 mesh 的权重索引、bindpose 数量必须一致；
4. 新增服装辅助骨必须带 mod 前缀（防撞名）并显式声明在 sidecar 中。

> ⚠️ **bindpose 是网格的属性，不是骨架的属性。** 运行时用 mesh 自带的 bindpose 配原版活体骨，
> 两者不自洽 = 静止偏移。契约钉的是"mesh 的 bindpose 等于什么"。

> ⚠️ **骨名一律用 transform 名。** `LeftArm`，不是 Humanoid API 的 `LeftUpperArm`。

第 2 条的可验证形式（尺子与闸门用的就是它）：

```text
D = 目标 bindPose · 源骨静止世界        自洽时 D = 单位阵
位置差 = |D 的平移|      朝向差 = D 旋转部分的转角
```

只量节点静止姿势的角度**不够** —— 前者过、后者不过的包会出现「闸门全绿而画面是另一个姿势」。

## 2. 五档状态

每根来源骨最终**只能**处于以下之一，**不允许"未决定"进入导出**：

| 档 | 含义 | 现状 |
|---|---|---|
| `direct` | 直接映射到一根学马骨 | 表单填目标骨（唯一） |
| `merge` | 合并到一根学马骨（多对一） | 一组多根填同一目标骨，或 rigid / follow_* 策略 |
| `helper` | 保留为新增辅助骨，挂在学马骨架下 | 策略选「自建摇物链」/「原版布料驱动器」 |
| `bake` | 静止形变烘进网格后合并到父级学马骨 | ✅ 策略 + `gmi.bake_rest_offset` 算子；标了没烘就导出会被拦（`operators._prepare_bundle_export_data` 的未烘检查） |
| `reject` | 无法安全处理，禁止导出 | ✅ 策略已在表单；有这档的骨直接拦下导出（`operators._prepare_bundle_export_data` 的 `reject` 检查） |
| `undecided` | 还没决定 | 装饰骨的正常起点；**默认拦下导出**，显式放行会写进 sidecar（闸门 9，`40819e4`） |

判定是纯函数 `core.row_state(target, strategy, shared_target)`，UI 与闸门读同一个它。

**绝对不能让插件静默把未知来源骨猜成某根学马骨。** 五档状态就是这个标注 —— 它是**决定**
不是猜测，必须显示在表单里。

### 赋值粒度是组，不是骨

一根一根选 `helper` 就是原样重演痛点（chisaki 的 MMD 裙子作者手点了几十次）。分组信号
**一个骨名都不读**（`core.structural_bone_groups`）：

| 信号 | 怎么算 |
|---|---|
| 锚点 | 沿父链向上第一根身体骨（父链上没权重的中间骨不算断链） |
| 链 | 连通分支，**分叉即断** |
| 归组 | 同锚点 + 链长相同 ±1 |

表单一行 = **分组器给出的一行**，行上的决定落到这一行内的每一根骨；要逐根不同就按行尾的「拆开这一组」。
装饰骨没有目标骨是**正常状态**，报警语义是「这一组还没决定」，不是「没指定目标」。

> ⚠️ **「行」既不等于结构组，也不等于物理作用域。** dress-2219 实测：表单多数行只有单根骨，
> 而一个结构组能装下 **57** 根（整条下半身）。**物理指令的作用域是链，不是组**（`cf12f94`）——
> 按组下指令会静默吞掉作者的 `follow_skirt`、让挂饰左右不对称。把「行=组」当成
> 「行上的物理决定覆盖整组」正是那个 bug 的思想来源。

> 未做：§4.3 列的第三个信号"影响顶点在网格上连片"。锚点 + 链长已经把 12 片裙摆并成一行；
> 同锚点同链长的尾巴混进裙摆那一行时拆开逐根覆盖即可。

## 3. 尺子与阈值（代码即契约）

| 量什么 | 在哪 | 阈值 |
|---|---|---|
| 逐骨位置差 / **静止朝向差** | `core.rest_alignment` | 朝向 5° 黄 / 15° 红；位置按骨长 10% 判黄，2mm 以下一律绿，**位置最高只判黄** |
| 跨关节权重混合带 | `core.cross_joint_bands` + `cross_joint_band_findings` | 低于原版同关节 = 黄；低于四成 = 红；原版自己低于 2% 的关节不判 |
| 承重关节零权重 | `core.critical_coverage_error` | 21 根，缺一个即拒绝导出 |

### 3.1 朝向的定义是「本骨 → 人形子骨」的方向

不是骨自身坐标系的整体转角。这条是标定出来的，别改回去：

```text
2026-08-17 拿**原版自己的身体**当作者模型量（唯一天然对齐的骨架）：
  按整体转角（含绕骨轴 roll） 104 根里 69 根正好 180° → 原版自己全红
  按本骨→人形子骨的方向       104 根全绿，0.00° / 0.00mm
```

原因：插件重建参考骨架时 roll 就没保留（`_create_armature` 只按 head→tail + 默认 roll 建骨），
镜像那一侧正好差 180°。而 lossless 路径下 `M_game × B_source` 本身就是重定向，
**roll 不要求逐根对齐**。同时事实文档 §6.2 已经记了另外两个坑：不能用 head→tail
（Biped 的 tail 约定给反向），不能把全部子骨平均（衣物骨会把方向拽反，报 154°）。

阈值背书：烘对了的包 39 根人形骨残差全 0.0°；坏样本 52°~172°；"腿/躯干看着正常"那一档是 7°。
位置**只判黄**：lossless 把静止位置差当重定向吸收（"免的是位置"），会炸的是朝向。
位置按骨长判：手指骨节 20~25mm、四肢 150~300mm，一个绝对毫米数两头都判错。

朝向是作者唯一自查不到的东西：静止截图完全正常，转身之后手臂转到身后、手指拉成面条
（实机三次坐实，肩差 172°），而且它不在头/手/脚/根骨这几个容易抽查的位置上。
所以闸门必须查**全部 `direct` 映射骨**，不是抽查几个。

### 3.2 跨关节带的原版真值与两个坑

**肩 13.3% / 肘 3.9% / 腕 6.2% / 膝 9.5%**（场景里有带权重参考体时用参考体现算，
拿不到才用这张表；2026-08-17 复核：拿原版自己的身体现算，四项与表逐项相同）。

⚠️ **带宽随"没映射的源骨怎么解析"变化**，量之前必须先说清用的是哪种解析。同一副
Claymore rip、同一个网格：

```text
只按身体骨映射（扭转骨被丢掉）      肩 0.0%   肘 2.7%   腕 0.0%   膝 5.1%
按导出实际解析（扭转骨落到锚点骨）  肩 3.6%   肘 1.6%   腕 6.1%   膝 5.1%
2026-08-16 记录值（处理后的成品）   肩 4.9%   肘 2.6%   腕 6.2%   膝 8.2%
```

所以面板用的是**与导出同一份解析**（`_resolve_source_bone_remap(..., skeleton)`）。
三组的结论一致：**跨肩带只有原版的四分之一到三分之一 → 红**，腕与原版持平。
数字对不上到小数位是因为输入不同（原始 FBX + 预设映射 vs A→T 烘完、认领扭转骨、
重定向过手部几何的成品），那个中间产物没留下可复现的版本。

## 3.3 参考资产（作者对齐的唯一基准）

就是步骤①的「导入参考模型与骨架」，不另造资产。契约：**与原版逐骨 diff 为零**
（`tests/blender_reference_rig_smoke.py`，位置 / 朝向 / 父子关系 / 节点覆盖）。

| 进参考 | 怎么来 |
|---|---|
| 带权重骨的静止位置 + 朝向 | `bindPose` 求逆，写进 `EditBone.matrix`（head + 方向 + roll 一次定死） |
| 无权重节点（`Reference`/`Pelvis`/链锚点 `*_A` `*_O`/链根 `*_S`） | 没有 bindPose，从最近的带权重祖先按**完整 local 矩阵**合成 |
| 各骨的权重分布 | 参考体网格自带的顶点组（游戏原生权重），P3 劈权重就从这里投影 |
| 缩放与坐标系 | 导入时换算，作者侧不需要再动 |

骨长（tail 距离）**不是判据**：Unity 没有"骨长"这个概念，参考骨的 0.05m 纯粹为了看得见。

不进参考：原生 Animator / IK / 驱动器 / 碰撞体、原版动态链的 `active`/`around`/`collisionMask`
—— 这条路线下它们原封不动留在游戏里，搬进 Blender 是无用功。

**socket 节点不在 body 的骨列表里**（150 根里 18 个无权重节点全是链锚点）；手持道具挂点在
角色/手部 prefab 上。这条路线不碰 socket，所以不补。

## 4. 分区取舍（要写进 UI 的一句话）

「尽量保留源权重」和「肩膀不崩」在**人体贴身区是对立的** —— 源自己跨肩带只有 4.9%，
保留它就是保留崩坏。分区不是折中，是各取所长：

**辅助骨区保源权重（细节全在），人体区缺骨处取原版（过渡带质量）。**

## 5. 缺骨怎么补（档 1 的施工方案）

`core.redistribute_family_weight`，逐顶点、只对缺的那几根骨：

```text
族 = {缺的那根骨} ∪ (作者在这个顶点上有权重 ∩ 原版在最近那点上有权重)
分给缺骨的比例 = 原版的 share / 族内原版权重之和
剩下的按**作者自己的比例**分回捐赠骨          族内总量不变
```

三条不可让的规矩：作者有权重、原版在那点没有的骨**不进族**（那是作者的画法，§7.3 档 2）；
**总量守恒**，不重绘全身；原版只决定"分多少给缺骨"，捐赠骨之间的相对比例是作者的（要求 2）。

验收是可复算的：把**原版自己身体**的 `LeftShoulder` 整组删掉再归一化，劈回来与真值逐顶点比 ——
864 个顶点最差 5.96e-08（`tests/blender_weight_split_smoke.py`）。

> **引用代码只写符号名，不写行号。** 2026-08-20 核对：18 条行号引用里 6 条已指到不相干的函数，
> 且漂移全由同一周自己的提交造成。详见架构文档「贯穿不变量」。
