# 反面教训汇总（工具链）

这份文档只记**做错过什么、为什么错、结论是什么**。测量数据、脚本和逐轮验证过程留在各自
的原始文档里，这里不重复。动手前扫一眼，能省掉已经交过的学费。

---

## 1. 已排除的整条路线

| 路线 | 为什么排除 |
|---|---|
| **3DMigoto 逆蒙皮** | 数学上做到了实机贯通，代价全在工程面：必须传权（作者不能用自己的权重）、贴图按寄存器硬绑（shader 变体一换就整体错乱）、换的是已蒙好皮的最终几何所以**新增物理骨不可能**、描边和透明都要 hack。AB 路线把这些换成一次性的打包门槛 |
| **PC IL2CPP 进程内注入** | 它证明的命题（外部模型可由引擎自蒙皮）正是 AB 路线在做的事，而 AB 走正规资产管线不需要注入；且探针产物同样叫 `xinput1_3.dll`，与生产 runtime 撞名 |
| **照搬 GIMI / WWMI** | 学马是 **CPU 蒙皮**，抓帧拿到的 `VB0` 是已蒙皮的当前姿势，没有骨骼/权重/T-pose。那套家族方法的前提在这里不成立 |

3DMigoto 本身没被放弃——它现在唯一的角色是抓帧工具。

## 2. 已作废且有害的旧做法

- **未映射骨骼兜底填 `Hips`**。它把「没认出来」变成「静默出废品」，正是承重关节闸门要
  拦的东西。0.9.0 起改为骨骼映射表 + 闸门，缺权重直接拒绝导出并点名。
- **拼接原生身体网格做半透明/裸露区**。开放边会出描边锯齿。身体**始终用单张封闭网格**。
- **自建镂空 / 半透明路线**。只保留游戏原生 `m_bdyco`；它是 cutout，不是连续半透明，
  薄纱和玻璃不在支持范围。
- **按位置猜装饰骨的物理归属**。实测只有 1/3 命中——源作者常把腰饰绑在胸骨、把裙边花边
  绑在大腿上。名字同样不可靠（`lace` 可能在靴口）。默认给一个不会炸的策略，由作者一句话
  覆盖，才是对的形状。
- **把装饰骨也翻译到游戏骨**。身体骨必须接到游戏活体骨，装饰骨才整搬；硬翻译会让缎带
  黏裙、蝴蝶结裂开。

## 3. 被推翻的结论

| 曾经的结论 | 实况 |
|---|---|
| hair 的 `t0.A` 应默认清零 | **错**。清零会关闭刘海覆盖，眉毛和眼睛透不出来。现在默认保留作者 Alpha |
| 「骨到主导几何距离 ÷ 骨长 > 1.0」可作绝对判据 | **错**。健康且实机能跑的模型里这很常见。只能同模型前后对比，不能用绝对阈值 |
| 摆动物理的「1 层墙」是运行时够不着层结构 / 组件拓扑不对 | **错**，两轮都是误诊。真因是导出器漏了链尾 tip 骨——`UpdateChainInfo` 本就排除每条链最后一根，缺 tip 就等于少一节。数据补齐后它自己就对了，**别手搭 layer，也别再逆向它** |
| 指尖 `|x|max` 与游戏差 <20mm 可作绑定质量判据 | **模型相关**。那个模型最外侧恰好是指尖；宽袖/飘带服装最外侧是袖子，判据会量到袖子而漏过坏绑定 |
| 源/游戏逐骨朝向差 90~180° 是问题 | **无害**，是 Blender 骨轴约定差。四肢同样差却正常 |

## 4. 外部模型转换的硬教训

- **左右镜像必须最先确认。** 插件坐标约定是「Blender 所见 = 游戏画面的镜像」，mmd_tools
  导入的 PMX 手性是正的，不先整体 X 镜像，印花和文字进游戏就是反的。
- **姿势参考只信指定文件。** 别信任意 blend 里的骨架姿势——踩过「参考骨架实际是 37°
  A-pose 摆拍状态」的坑。
- **对齐必须是全骨架 retarget，不是只对手臂。** 只对手臂的结果是「手对了、人歪着」。
  脊椎逐关节直接映射，别按弧长比例插值；腿要先 mute IK/约束再做 FK 对齐。
- **图集 UV 层必须改名 `UV0` 并删掉多余层**，否则导出器烘错 UV、颜色全乱。
- **游戏参考模型存独立 blend**，别让它活在管线中间产物里——上游脚本重跑会把它连锅端掉。
- **坏绑定只能回上游重做 prep，导出侧补不了。** 五条补救弯路都已实测证伪：改用源骨架
  bindpose（静止直接崩）、传递权重（更糟）、逐顶点 `gameRest·sourceRest⁻¹` retarget（手指
  绕自身轴扭烂）、pose 摆源骨再烘（网格离关节更远）、把朝向差当病因（本来就无害）。
- **AB 路线比 3DMigoto 更不容错**，这不是 AB 的 bug：3DMigoto 有逐影响 `BoneCorrections`
  在运行时校正源/游戏骨架差异，AB 是标准 LBS，没有这一层。同一个源 3DMigoto 版能动、
  AB 版炸，说明 prep 质量要求被提前了。

## 5. 贴图与顶点色的坑

- **换模没描边的真因是顶点 COLOR。** 游戏描边读顶点 COLOR，新网格缺 COLOR 会被默认白色
  冲掉。**不是 ini 问题、不是法线问题**，别往那边查。
- **透明区渲染成黑块**：透明区 RGB 留成纯黑会被双线性渗色混进来。保留 alpha 只外扩 RGB
  （alpha-bleed），DDS 用带 alpha 的 BC7/BC3，**不要为了省事把 t0 改成不透明**。
- **t1/t4 以预设库为准，别搬源游戏的 ramp 色。** 各浪费过一轮进游戏验证：`t4.A` 全填 1 →
  整套衣服泛粉；`t4.RGB` 用源 ramp 阴影色线性相乘 → 衣服压成死黑；`t1.A` 搬源游戏白 AO →
  袖子大片白斑。
- **hair 的 t1.A 写高 → 蓝紫斑纹 / 旧发色泄漏**：插件不替换 t6 发丝高光图，换过 UV 的新
  发型会错采原角色的 t6。自定义 UV 一律 A=0。
- **只换 t0 不换 t4**，暗面会继续读原服装的 `sdw`，出现不属于这件衣服的图案。
- **hair 的贴图语义 ≠ body**，别把 body 那套直接搬过去。

## 6. 流程与工具

- **抓帧一次只按一次 F8**，按完等磁盘写完；`share_dupes` 去重目录里的单个文件不要手删。
- **导出成功不等于能用。** 承重关节闸门存在的原因就是：旧版会导出成功、进游戏才发现整只
  手被钉在 `Spine1`，全程零警告。
- **动手前先查已有工作区。** 有过直接开工、做完才发现同一件事上游早有成熟流程的先例。
