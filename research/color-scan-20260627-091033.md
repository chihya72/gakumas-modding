## Safe parameter conclusion

The capture confirms that original COLOR is region/topology data, not a material-wide constant. Reusing the top original values on a custom skirt can activate the same shader branch on the wrong geometry and cause the moving dark/blue blocks.

The safe family should neutralize `R/G/A`, keep `B` high nibble at `0xf0`, and use only `B` low nibble as outline width:

| Meaning | Safe COLOR rgba8 |
|---|---|
| outline off | `(0, 0, 240, 0)` |
| thin outline | `(0, 0, 243, 0)` |
| medium outline | `(0, 0, 248, 0)` |
| full outline | `(0, 0, 255, 0)` |

Recommended default remains `(0, 0, 255, 0)`. If full width looks too different from the game's region-varying outline, test `(0, 0, 248, 0)` first, then `(0, 0, 244, 0)` or `(0, 0, 243, 0)`.

Avoid using these original captured values as material presets for custom topology:

- `(34, 63, 15, 144)`
- `(34, 57, 15, 144)`
- `(81, 0, 15, 144)`
- `(17, 70, 15, 144)`
- `(0, 16, 15, 144)`
